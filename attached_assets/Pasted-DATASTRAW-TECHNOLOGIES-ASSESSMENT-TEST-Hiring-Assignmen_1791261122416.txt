PART 1 - BUILD

AI-Powered CX Reply Assistant

Build a small application that helps a customer support agent generate an AI-assisted response to a customer.

This should be a working, deployed application, not just a prototype on your local machine.

Scenario:

A CX agent is handling a customer conversation.

The customer says:

"My order was delivered but the bottle is broken. What can I do?"

The agent should be able to use your application to understand the conversation, access relevant brand

information, and generate an appropriate response.

Core Requirements:

1. Conversation View



Create a simple interface showing:

● Customer name

● Brand

● Conversation history

Datastraw Technologies Pvt Ltd | Private & ConfidentialLatest customer message

● Basic order information

You may use mock data.

Additionally, include a way to switch between the Customer and Agent side of the conversation (e.g. a toggle

or two views) so a message can be sent as the customer and the agent side can then generate/send a reply to it.

This is meant to let you (and us, when reviewing) test the AI reply loop end-to-end, not just view seeded mock

data.

2. Brand Knowledge Base



Create a knowledge base for at least two different brands, each containing at minimum:

● Return policy

● Refund policy

● Shipping policy

● Cancellation policy

The content can be mocked, but each brand's policies should differ meaningfully (e.g. different refund

windows) so it's possible to verify that Brand A's knowledge is never used when responding to a Brand B

customer.

Whatever retrieval approach you use (keyword matching, embeddings/vector search, or otherwise) is your

choice for a KB this size, either is a defensible answer, and we're more interested in you being able to justify

the trade-off than in which one you pick.

What matters is that the knowledge base content itself is manageable through the application, a

create/edit/delete interface for KB entries per brand, even a simple one. This lets us change a policy ourselves

and re-test the AI's behavior without touching your code or database directly.

The system should retrieve the relevant brand-specific information when generating a response.

3. AI Reply Generation:



The agent should be able to click:

Generate Reply

The application should:

1. Identify the relevant brand.


2. Retrieve relevant information from the knowledge base.


3. Provide the appropriate context to an LLM.


4. Generate a suggested customer response.


5. Display the response to the agent, along with the retrieved knowledge/context that was used to



generate it.

The agent should then be able to:

● Edit the response

● Regenerate the response

● Approve the response

● Compose and send a manual message directly, independent of the AI, so the conversation supports

a real back-and-forth, not just a single generate-and-approve action.

Actual WhatsApp or email delivery is not required; sending into the app's own conversation view is sufficient.
4. AI Guardrails:

The AI should not simply answer every question confidently.

For example, if the knowledge base says:

Refunds are only permitted within 7 days of delivery.

and the customer asks:

"I received this 20 days ago. Can I get a refund?"

The system should not confidently promise the customer a refund.

Think about how you would constrain the AI to the information available to it and what should happen when

the required information is unavailable.

Also consider what happens when the knowledge base has no relevant information at all for the customer's

question. What should the AI do in that case, and how should that be reflected to the agent?

5. Data & Logging:



Store the relevant information, such as:

● Customer message

● Retrieved context/knowledge

● AI-generated response

● Agent-edited response

● Final response

● Timestamp

You do not need to build a complete CRM.

We are looking for one well-built piece of a real CX product.
